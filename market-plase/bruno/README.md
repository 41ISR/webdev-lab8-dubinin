# Bruno API Collection - Инструкция по использованию

## Что такое Bruno?

Bruno - это современный API клиент (альтернатива Postman), который хранит коллекции запросов в виде файлов прямо в вашем репозитории. Это удобно для:
- Версионирования API запросов вместе с кодом
- Работы в команде (все видят одни и те же запросы)
- Отсутствия необходимости в облачной синхронизации

## Установка Bruno

1. Перейдите на сайт: https://www.usebruno.com/
2. Скачайте версию для вашей ОС (Windows/Mac/Linux)
3. Установите приложение
4. Запустите Bruno

## Открытие коллекции

### Способ 1: Через интерфейс Bruno

1. Откройте Bruno
2. Нажмите **"Open Collection"** (или File → Open Collection)
3. Выберите папку `market-plase/bruno-collection`
4. Коллекция откроется в левой панели

### Способ 2: Перетаскивание

1. Откройте Bruno
2. Перетащите папку `bruno-collection` в окно Bruno
3. Коллекция автоматически откроется

## Структура коллекции

```
bruno-collection/
├── Auth/                    # Аутентификация
│   ├── Register.bru        # Регистрация
│   ├── Login.bru           # Вход
│   └── Get Me.bru          # Получить текущего пользователя
├── Items/                   # Товары
│   ├── Get All Items.bru   # Список всех товаров
│   ├── Create Item.bru     # Создать товар
│   └── Delete Item.bru     # Удалить товар
├── Bids/                    # Ставки
│   ├── Get Item Bids.bru   # Ставки на товар
│   ├── Create Bid.bru      # Создать ставку
│   └── Get My Bids.bru     # Мои ставки
├── Stats/                   # Статистика
│   └── Get Stats.bru       # Статистика платформы
└── environments/            # Окружения
    └── Production.bru      # Продакшн окружение
```

## Настройка окружения (Environment)

### Шаг 1: Выбор окружения

1. В правом верхнем углу Bruno найдите выпадающий список окружений
2. Выберите **"Production"**

### Шаг 2: Переменные окружения

В окружении уже настроены переменные:
- `baseUrl` = `https://kitek.ktkv.dev/marketplace` (базовый URL API)
- `token` = пустая строка (будет заполнена автоматически после логина)
- `itemId` = пустая строка (будет заполнена после создания товара)

## Пошаговая инструкция по тестированию API

### 1. Регистрация нового пользователя

1. В левой панели откройте **Auth → Register**
2. В центральной панели увидите:
   - **URL**: `{{baseUrl}}/api/auth/register`
   - **Method**: POST
   - **Body**: JSON с данными пользователя
3. Измените данные в Body (если нужно):
   ```json
   {
     "username": "ваше_имя",
     "password": "ваш_пароль",
     "email": "ваш@email.com"
   }
   ```
4. Нажмите кнопку **"Send"** (или Ctrl+Enter)
5. В нижней панели увидите ответ:
   ```json
   {
     "success": true,
     "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
     "user": { ... }
   }
   ```
6. **Токен автоматически сохранится** в переменную `token` (благодаря тестам)

### 2. Вход в систему (если уже зарегистрированы)

1. Откройте **Auth → Login**
2. Измените username и password в Body
3. Нажмите **"Send"**
4. Токен автоматически сохранится

### 3. Проверка авторизации

1. Откройте **Auth → Get Me**
2. Нажмите **"Send"**
3. Должны увидеть информацию о вашем пользователе
4. Если получили ошибку 401/403 - токен не сохранился, повторите Login

### 4. Получение списка товаров

1. Откройте **Items → Get All Items**
2. Нажмите **"Send"**
3. Увидите массив всех товаров на платформе

### 5. Создание товара

1. Откройте **Items → Create Item**
2. Измените данные товара в Body:
   ```json
   {
     "title": "Название вашего товара",
     "description": "Подробное описание",
     "price": 10000,
     "imageUrl": "https://example.com/image.jpg"
   }
   ```
3. Нажмите **"Send"**
4. **ID созданного товара автоматически сохранится** в переменную `itemId`

### 6. Просмотр ставок на товар

1. Откройте **Bids → Get Item Bids**
2. Убедитесь, что переменная `itemId` заполнена (или введите ID вручную в URL)
3. Нажмите **"Send"**
4. Увидите список ставок на товар

### 7. Создание ставки (нужен второй пользователь!)

**ВАЖНО**: Нельзя делать ставку на свой товар!

1. Зарегистрируйте второго пользователя (Auth → Register с другими данными)
2. Откройте **Bids → Create Bid**
3. Убедитесь, что `itemId` указывает на товар другого пользователя
4. Измените сумму ставки (должна быть выше текущей):
   ```json
   {
     "amount": 15000
   }
   ```
5. Нажмите **"Send"**

### 8. Просмотр своих ставок

1. Откройте **Bids → Get My Bids**
2. Нажмите **"Send"**
3. Увидите все ваши ставки с информацией о том, лидируете ли вы

### 9. Удаление товара

1. Откройте **Items → Delete Item**
2. Убедитесь, что `itemId` указывает на ваш товар
3. Нажмите **"Send"**
4. Товар будет удален (если на него нет ставок)

### 10. Статистика платформы

1. Откройте **Stats → Get Stats**
2. Нажмите **"Send"**
3. Увидите общую статистику: количество товаров, пользователей, ставок и т.д.

## Работа с переменными

### Просмотр переменных

1. Нажмите на иконку **"Environments"** в правом верхнем углу
2. Выберите **"Production"**
3. Увидите все переменные и их значения

### Ручное изменение переменных

1. Откройте окружение Production
2. Измените значение переменной (например, `itemId`)
3. Сохраните (Ctrl+S)

### Использование переменных в запросах

В любом месте запроса используйте синтаксис `{{имя_переменной}}`:
- URL: `{{baseUrl}}/api/items/{{itemId}}`
- Headers: `Authorization: Bearer {{token}}`
- Body: `"userId": {{userId}}`

## Вкладки в Bruno

### 1. Params (Параметры)
Для GET запросов с query параметрами (в нашем API не используется)

### 2. Headers (Заголовки)
Автоматически добавляются:
- `Content-Type: application/json`
- `Authorization: Bearer {{token}}` (для защищенных запросов)

### 3. Body (Тело запроса)
Для POST/PUT запросов. Выберите тип:
- **JSON** - для нашего API (уже выбран)
- Text, XML, Form и др.

### 4. Auth (Аутентификация)
Настройка авторизации:
- **None** - для публичных эндпоинтов
- **Bearer Token** - для защищенных (использует `{{token}}`)

### 5. Docs (Документация)
Описание запроса, примеры ответов, возможные ошибки

### 6. Tests (Тесты)
Автоматические проверки ответа:
```javascript
test("Status code is 200", function() {
  expect(res.status).to.equal(200);
});
```

## Автоматические тесты

После каждого запроса в нижней панели увидите результаты тестов:
- ✅ Зеленая галочка - тест прошел
- ❌ Красный крестик - тест не прошел

Тесты также автоматически сохраняют важные данные:
- После Login/Register → сохраняется `token`
- После Create Item → сохраняется `itemId`

## Полезные горячие клавиши

- **Ctrl+Enter** - отправить запрос
- **Ctrl+S** - сохранить изменения
- **Ctrl+N** - новый запрос
- **Ctrl+F** - поиск по коллекции

## Типичные ошибки и решения

### Ошибка 401 Unauthorized
**Причина**: Не авторизованы или токен истек
**Решение**: Выполните Login заново

### Ошибка 403 Forbidden
**Причина**: Недействительный токен или нет прав
**Решение**: Проверьте, что токен правильный, выполните Login

### Ошибка 400 Bad Request
**Причина**: Неверные данные в запросе
**Решение**: Проверьте Body запроса, все обязательные поля должны быть заполнены

### Ошибка 404 Not Found
**Причина**: Товар не найден
**Решение**: Проверьте `itemId`, возможно товар был удален

### Переменная не подставляется
**Причина**: Не выбрано окружение
**Решение**: Выберите "Production" в правом верхнем углу

## Экспорт/Импорт

## Дополнительные возможности

### Запуск всех запросов подряд
1. Правый клик на папке (например, Auth)
2. Выберите **"Run Folder"**
3. Все запросы выполнятся последовательно

### Дублирование запроса
1. Правый клик на запросе
2. **"Duplicate"**
3. Измените под свои нужды

### Создание нового запроса
1. Правый клик на папке
2. **"New Request"**
3. Настройте URL, метод, body и т.д.
